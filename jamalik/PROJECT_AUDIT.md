# تدقيق مشروع «Beauty Vibes»

مراجعة نهائية لحالة المشروع قبل النشر: ما بُني فعلًا، وكيف تحقّقنا منه،
وما حدوده المعروفة، وما الخطوات التالية المقترحة.

**تاريخ التدقيق:** ٧ أغسطس ٢٠٢٦
**حالة البناء:** `npm run lint` و `npm run typecheck` و `npm run build` تمرّ بلا أخطاء ولا تحذيرات.

---

## ١. البنية (Architecture)

### الحزمة التقنية ولماذا

| الطبقة | الاختيار | السبب |
|---|---|---|
| الإطار | Next.js 16 (App Router) | توليد ساكن + تصيير على الخادم في مشروع واحد، وهو ما يحتاجه موقع محتوى يعتمد على السيو والسرعة. |
| اللغة | TypeScript (strict) | يمنع صنفًا كاملًا من الأخطاء قبل التشغيل، ويجعل التوسّع لاحقًا أقل خطرًا. |
| التنسيق | Tailwind CSS v4 | خصائص منطقية (`ps-`/`pe-`/`start`/`end`) تعمل في RTL دون إضافات، وحجم CSS النهائي صغير. |
| قاعدة البيانات | PostgreSQL 16 | علاقات واضحة، بحث نصّي قابل للتطوير، ومصفوفات أصلية للكلمات المفتاحية. |
| ORM | Prisma 6 | نضج وتوثيق واسع وهجرات موثوقة. اخترنا 6 بدل 7 عمدًا: الإصدار السابع يفرض محوّلات تعريف جديدة ما زالت حديثة العهد. |
| المحتوى | Markdown + unified/rehype | مصدر واحد نظيف، مع تعقيم صارم عند العرض. |
| المصادقة | تنفيذ خاص (bcryptjs + جلسات على الخادم) | لا حاجة لمزوّدات خارجية؛ سطح هجوم أصغر وتحكّم كامل. |

### تنظيم الملفات

```
src/
├── app/
│   ├── (site)/              صفحات الموقع العام (ترويسة/تذييل مشتركان)
│   ├── admin/
│   │   ├── login/           صفحة الدخول (خارج حارس الجلسة)
│   │   └── (dashboard)/     كل صفحات اللوحة خلف requireUser
│   ├── actions/             Server Actions مقسّمة حسب المجال
│   ├── api/                 Route Handlers (عدّاد القراءات)
│   ├── sitemap.ts robots.ts rss.xml/
├── components/
│   ├── layout/ article/ forms/ newsletter/ admin/ ads/ analytics/ seo/ ui/ search/
├── features/archive/        منطق صفحات الأرشيف المشترك بين المسار والصفحة المرقّمة
├── lib/
│   ├── auth/                تجزئة كلمات المرور، الجلسات، الحُرّاس
│   ├── queries/             كل وصول للقراءة إلى قاعدة البيانات
│   ├── seo/                 بناة الميتا، البيانات المنظّمة، فحص السيو
│   ├── email/               تجريد مزوّد النشرة البريدية
│   └── prisma settings markdown validation rate-limit slug format analytics
├── config/                  ثوابت الموقع والتنقّل
└── middleware.ts            حاجز مبكّر أمام /admin
```

**قرارات بنيوية تستحق الذكر:**

- **منطق الأرشيف مشترك.** `features/archive/*` يحتوي المنطق مرة واحدة، وملفات المسار
  (`/articles` و `/articles/page/[number]`) أغلفة رفيعة. بلا هذا كان المنطق سيتكرّر ثماني مرات.
- **الترقيم بمسارات لا بمعاملات استعلام.** `?page=2` كان يجبر كل صفحات الأرشيف على
  التصيير الديناميكي (قراءة `searchParams` تُلغي التوليد الساكن). `/page/2` سمح بتوليدها
  كلها ساكنة.
- **الهجرات تعمل في البناء لا يدويًا.** `vercel-build` ينفّذ
  `prisma migrate deploy` ثم تعبئة مشروطة بـ `RUN_SEED` ثم `next build`.
  التعبئة مشروطة عمدًا: هي idempotent لكنها تعيد كتابة محتوى المقالات، فتشغيلها
  مع كل نشر كان سيُلغي تعديلات المحرّرة.
- **`lib/markdown-text.ts` منفصل عن `lib/markdown.ts`.** فحص السيو الحيّ يعمل في المتصفّح؛
  استيراده من الملف الذي يستورد سلسلة unified كان سيضيف عشرات الكيلوبايتات إلى الحزمة.

## ٢. المزايا المنجزة

### الموقع العام
- الرئيسية: مقال غلاف، أحدث المقالات، الأكثر قراءة، اختيارات المحررات، شبكة التصنيفات، نصائح سريعة، نشرة بريدية.
- `/articles` وأرشيف مرقّم `/articles/page/N`.
- `/article/[slug]`: مسار تنقّل، صورة بارزة، بيانات الكاتبة، تاريخا النشر والتحديث، زمن القراءة، فهرس محتويات، محتوى منسّق، وسوم، أزرار مشاركة، أسئلة شائعة، صندوق الكاتبة، دعوة للنشرة، مقالات ذات صلة.
- `/category/[slug]` و `/author/[slug]` و `/tag/[slug]` وكلها مرقّمة.
- `/search`: بحث في العنوان والمقتطف والمحتوى والوسوم والتصنيفات.
- ثماني صفحات ثابتة: من نحن، اتصلي بنا، النشرة، وست صفحات سياسات بمحتوى فعلي.
- صفحة ٤٠٤ مخصّصة بمخارج مفيدة.

### لوحة التحكم
- لوحة معلومات: ثمانية مؤشرات، الأكثر قراءة، آخر التعديلات، حالة السيو، حالة التكاملات.
- المقالات: إنشاء/تحرير/حذف، مسودّة/نشر/جدولة، تبديل سريع للحالة، تصفية وبحث وترقيم.
- محرّر المقال: كل حقول السيو، محرّر أسئلة شائعة، حقل وسوم متعدّد القيم، فحص سيو حيّ.
- التصنيفات والكتّاب: CRUD كامل مع حماية من حذف عنصر له مقالات.
- الرسائل والمشتركون: عرض وتغيير حالة وحذف.
- الإعدادات: هوية الموقع، GA4، Search Console، AdSense، الشبكات الاجتماعية.
- الحساب: بيانات الحساب وتغيير كلمة المرور.

### المحتوى
٣٨ مقالًا منقولًا من مدونة Blogger قائمة (١٠ جمال طبيعي، ٨ صحة وتغذية، ٧ شعر،
٥ بشرة، ٣ جسم، ٣ صحة المرأة، ٢ منتجات)، وسبعة تصنيفات، وكاتبة واحدة، و١٥ وسمًا.

المحتوى التجريبي الذي رافق بناء المشروع (١٥ مقالًا و٤ كاتبات و٥ تصنيفات) أُزيل
بالكامل. تفاصيل النقل وفحوصه في [`MIGRATION_REPORT.md`](./MIGRATION_REPORT.md).

### البيانات المنظّمة

`Organization` و `WebSite` (مع `SearchAction`) تُعرَّف مرة واحدة في تخطيط الموقع وتشير
إليها بقية الصفحات بالمعرّف. ولكل نوع صفحة ما يناسبها: `WebPage`، `BlogPosting`،
`BreadcrumbList`، `Person`، `CollectionPage`.

**`FAQPage` لا يُضاف إلا حين تكون الأسئلة معروضة فعلًا للزائر** — الترميز المضلّل سبب
شائع للعقوبات اليدوية، ولا نستخدمه.

### فحص السيو داخل المحرّر

أربعة عشر فحصًا مرجّحًا (وصف الميتا، الكلمة المفتاحية وموضعها، الصورة ونصّها البديل،
H1 واحد، العناوين الفرعية، طول المحتوى، الروابط الداخلية، الرابط، المقتطف، canonical)
مع نتيجة من ١٠٠ تتحدّث أثناء الكتابة.

**النتيجة معلَّمة صراحة في الواجهة بأنها تقدير داخلي إرشادي، وليست تقييمًا من Google
ولا مؤشرًا على الترتيب.**

## ٤. Google Analytics 4

- معرّف القياس يُدار من **الإعدادات**، وتتقدّم قيمته على `NEXT_PUBLIC_GA_ID`.
- **لا يُحمَّل أي سكربت عند غياب المعرّف** (مُختبَر آليًا قبل التفعيل وبعده وبعد التعطيل).
- المعرّف يُتحقّق من صيغته (`G-XXXXXXXXXX`) قبل الحفظ وقبل الحقن.
- **سكربت واحد فقط** لكل صفحة — تأكّدنا آليًا من عدم التكرار.
- `send_page_view: false` مقصود: موجّه App Router لا يعيد تحميل الصفحة، فالإرسال
  التلقائي كان سيسجّل زيارة واحدة لكل جلسة. نرسل `page_view` يدويًا عند كل تغيّر مسار.
- `anonymize_ip` مفعّل.

**الأحداث المُنفَّذة:** `page_view`، `article_view`، `search`، `outbound_click`،
`newsletter_signup`، `contact_submit`، `share_click`.

## ٥. Google Search Console

قيمة وسم التحقق تُدخَل من الإعدادات وتُحقن تلقائيًا في `<head>` عبر `metadata.verification`.
تُقبل قيمة `content` فقط (لا الوسم كاملًا) ويُتحقّق من ذلك. عند تركها فارغة لا يُضاف أي وسم.
مُختبَر آليًا في الحالتين.

## ٦. Google AdSense

> **تنويه:** ما أُنجز هو **تجهيز تقني** للربط فقط. قبول الموقع في برنامج AdSense قرار
> من Google بعد مراجعة المحتوى والسياسات وحجم الزيارات. لا يقدّم هذا المشروع أي ادّعاء
> بالقبول ولا يضمنه.

- معرّف الناشر يُدار من الإعدادات ويُتحقّق من صيغته (`ca-pub-` + ١٠–٢٠ رقمًا).
- مفتاح رئيسي منفصل لإيقاف الإعلانات دون حذف المعرّف.
- **لا يُحمَّل سكربت AdSense ولا تظهر أي مساحة إعلانية بدون معرّف صالح.**
- خمسة مواضع: أعلى الصفحة، داخل المقال، بين المقالات، العمود الجانبي، أسفل المقال.
- كل موضع يحتاج معرّف وحدة إعلانية مستقلًا؛ الموضع بلا معرّف لا يُعرض أصلًا حتى لا
  تبقى مساحة فارغة.
- **ارتفاع محجوز مسبقًا لكل موضع** لتفادي انزياح التخطيط (CLS).
- **لا نوافذ منبثقة، ولا طبقات تغطّي المحتوى، ولا تشغيل تلقائي** — وهذا موثّق في
  صفحة سياسة الإعلانات العامة.
- كل مساحة تحمل كلمة «إعلان» فوقها و `aria-label` وصفيًا.

## ٧. الأمان

| الإجراء | التنفيذ |
|---|---|
| تجزئة كلمات المرور | bcrypt بـ ١٢ جولة |
| مقاومة كشف الحسابات | رسالة موحّدة + مقارنة وهمية بزمن مماثل عند عدم وجود البريد |
| الجلسات | سرّ عشوائي ٢٥٦ بت في كوكي HttpOnly؛ القاعدة تحفظ HMAC-SHA256 له فقط |
| قوة الجلسة | تسريب قاعدة البيانات وحده لا يكفي لانتحال جلسة — يلزم `AUTH_SECRET` أيضًا |
| مقارنة الرموز | `timingSafeEqual` |
| كوكي آمن | HttpOnly + SameSite=Lax + Secure في الإنتاج |
| CSRF | Server Actions تتحقّق من الأصل تلقائيًا؛ ومسار API يفحص `Origin` صراحة |
| تحديد المعدّل | الدخول (١٠/عنوان و٥/بريد كل ١٥ دقيقة)، النشرة (٥/ساعة)، التواصل (٣/ساعة)، العدّاد (٦٠/دقيقة) |
| مقاومة السبام | حقل خفي في كل نموذج عام |
| التحقّق من المدخلات | zod على **كل** مدخل، على الخادم دائمًا |
| تعقيم المخرجات | `rehype-sanitize` بقائمة سماح صارمة (لا script/style/iframe/معالجات أحداث) — مُختبَر بمدخلات XSS |
| حماية اللوحة | `middleware` يحجب مبكرًا + `requireUser()` يتحقّق فعليًا في كل صفحة وكل إجراء |
| صلاحيات | الإعدادات والرسائل والمشتركون للمدير فقط (`requireAdmin`) |
| تغيير كلمة المرور | يتطلّب كلمة المرور الحالية، ويُنهي كل الجلسات على كل الأجهزة |
| بيانات شخصية | عنوان IP يُهشَّم قبل الحفظ ولا يُخزَّن خامًا |
| فتح إعادة توجيه | `next` بعد الدخول يقبل المسارات الداخلية فقط |
| ترويسات | `X-Content-Type-Options`، `X-Frame-Options`، `Referrer-Policy`، `Permissions-Policy`، HSTS |
| الأسرار | لا مفاتيح في كود الواجهة؛ `.env` مستثنى من git و `.env.example` بقيم نائبة فقط |
| الصور الخارجية | لا تمرّ عبر مُحسِّن Next — تفاديًا للسماح بنطاقات عشوائية |

**لا توجد بيانات اعتماد ثابتة في الكود.** حساب المدير الأول يُنشأ من متغيرات بيئة
عند تشغيل `npm run db:seed`، والسكربت يرفض كلمة مرور أقصر من ١٢ حرفًا، ولا يعيد
تعيينها إن كان الحساب موجودًا.

## ٨. الأداء

- **١٠٤ صفحة مولّدة ساكنة** عند البناء: الرئيسية، كل المقالات، كل التصنيفات والكتّاب
  والوسوم وصفحات الترقيم، وكل الصفحات الثابتة.
- الديناميكي فقط: `/search` (يعتمد على الاستعلام) و `/api/articles/view` ولوحة التحكم.
- إعادة التوليد التدريجي: ٥ دقائق للرئيسية والأرشيف، ١٠ للمقالات، ساعة للصفحات الثابتة.
- **المقالات المجدولة تظهر تلقائيًا** عبر شرط الاستعلام + إعادة التوليد، دون مهمة دورية.
- الإعدادات مخزّنة مؤقتًا تحت وسم واحد يُبطَل عند الحفظ — فلا تُجبر كل صفحة على التصيير الديناميكي.
- تحسين الصور: AVIF ثم WebP، `sizes` مضبوطة، تحميل كسول عدا صورة الشاشة الأولى.
- أبعاد صريحة لكل صورة، ومساحات إعلانية بارتفاع محجوز → انزياح تخطيط قريب من الصفر.
- الخطوط: خطّان عربيان فقط بأوزان محدودة، `display: swap`، ذاتيّا الاستضافة عبر `next/font`.
- JavaScript في المتصفّح محدود عمدًا: الترويسة، فهرس المحتويات، النماذج، عدّاد القراءات.
  صفحات السياسات والأرشيف تعمل عمليًا دون JS.
- **لا سكربتات طرف ثالث إطلاقًا** ما لم تُفعَّل التكاملات من اللوحة.
- أزرار المشاركة روابط مباشرة — لا widgets ولا تتبّع خارجي.

## ٩. الوصولية

- HTML دلالي، وH1 واحد لكل صفحة (مُختبَر آليًا).
- رابط «تخطّي إلى المحتوى» أول عنصر في ترتيب التركيز (مُختبَر آليًا).
- حالة تركيز موحّدة وواضحة على كل عنصر تفاعلي.
- `aria-current` على الروابط النشطة، و`aria-expanded`/`aria-controls` على الأزرار الطيّة.
- كل النماذج بعلامات `label` مرتبطة، ورسائل الخطأ مربوطة بـ `aria-describedby`، والحقول
  الخاطئة تحمل `aria-invalid`.
- نتائج الإرسال تُعلن عبر `role="status"` و `aria-live`.
- الأسئلة الشائعة بعناصر `details/summary` الأصلية — تعمل بلوحة المفاتيح دون ARIA إضافي.
- الجداول بـ `caption` و `th[scope]`.
- `Escape` يغلق القائمة والبحث؛ فتح القائمة يمنع تمرير الخلفية.
- احترام `prefers-reduced-motion`.
- لا منع للتكبير (`maximumScale: 5`).
- عناوين الصناديق التنبيهية عناصر حقيقية لا محتوى مولّد بـ CSS (لأن الأخير قد لا يُنطق).
- تباين الألوان: النص الأساسي `#211e1c` على `#fcfaf8` بنسبة تتجاوز ١٥:١، والنص الثانوي
  `#6e655e` يتجاوز ٥:١ — كلاهما فوق حدّ AA.

## ١٠. الاختبارات التي أُجريت

### فحوص البناء
`npm run lint` (بلا تحذيرات) — `npm run typecheck` — `npm run build` (١٠٤ صفحة).

### فحوص المسارات
٢٥ مسارًا عبر HTTP: كلها ٢٠٠ عدا `/admin` (٣٠٧ إلى الدخول) و٤٠٤ للمسارات غير الموجودة
وصفحات الترقيم خارج النطاق (سلوك مقصود).

### اختبارات المتصفّح (Playwright / Chromium) — ٢٩ فحصًا، كلها ناجحة
محفوظة في المستودع: `tests/e2e.mjs` (`npm run test:e2e`).
- **التجاوب:** لا تمرير أفقي على ١٠ صفحات × ٧ عروض (٣٢٠، ٣٧٥، ٣٩٠، ٤٣٠، ٧٦٨، ١٠٢٤، ١٤٤٠).
- **البنية:** H1 واحد، فهرس محتويات يطابق العناوين، كل الصور تحمل `alt`، رابط التخطّي يعمل.
- **التفاعل:** قائمة الجوال، إغلاق بـ Escape، البحث من الترويسة.
- **النماذج:** اشتراك ناجح، بريد غير صالح مرفوض، رسالة تواصل ناجحة.
- **المصادقة:** تحويل الزائر، رفض كلمة المرور الخاطئة، دخول ناجح.
- **دورة المحتوى الكاملة:** إنشاء مقال من اللوحة ← ظهوره على الموقع ← حذفه.
- **الإعدادات:** فتح الصفحة، ورفض معرّف GA بصيغة خاطئة.
- **لا أخطاء في وحدة تحكم المتصفّح** على أي صفحة.

### اختبارات التكاملات
تفعيل GA4 وSearch Console وAdSense من اللوحة ثم التحقّق من الحقن، ثم تعطيلها والتحقّق
من الاختفاء التام. وتأكيد تحميل سكربت GA **مرة واحدة** فقط.

### اختبارات معالجة المحتوى
حقن `<script>` و `onerror` — كلاهما مُعقَّم. الروابط الخارجية تحصل على
`rel="noopener noreferrer nofollow"`. الروابط الداخلية تبقى كما هي. الجداول والصناديق
التنبيهية تُعرض بصورة صحيحة.

### اختبارات واجهة API
`/api/articles/view`: ٢٠٠ للطلب الصحيح، ٤٠٣ من أصل خارجي، ٤٠٠ لمدخل غير صالح.

### أخطاء اكتُشفت وأُصلحت أثناء التدقيق
1. **روابط فهرس المحتويات مكسورة** — كان الفهرس يُجمع قبل التعقيم، والتعقيم يسبق
   معرّفات العناوين بـ `user-content-`، فلا تطابق أي عنصر. نُقل الجمع إلى ما بعد التعقيم.
2. **عناوين الصناديق التنبيهية تختفي** — كانت تُمرَّر كسمة `data-` يزيلها المعقّم.
   صارت عنصرًا حقيقيًا في الشجرة (أفضل للقارئات الصوتية أيضًا).
3. **تمرير أفقي بـ ٩٩٩٩ بكسل** — مصيدة الروبوتات كانت تستخدم `left: -9999px`، وهي
   في صفحة RTL تُنتج فيضًا حقيقيًا. استُبدلت بأسلوب إخفاء بأبعاد بكسل واحد.
4. **انهيار تخطيط بطاقة الكاتبة** — `.article-body img { width: 100% }` كانت تتفوّق على
   `size-16` فتمدّ الصورة وتُصفّر عرض شقيقها. قُصرت القاعدة على صور Markdown فقط.
5. **التصاق الرابط المقترح بالمكتوب** — اقتراح الـ slug عند فقدان التركيز كان يملأ الحقل
   لحظة بدء الكتابة فيه. صار الاقتراح أثناء كتابة العنوان ويتوقّف عند أول تعديل يدوي.
6. **`initialFormState` يصل كـ `undefined`** — كان مُصدَّرًا من ملف `"use server"` الذي لا
   يسمح إلا بتصدير الدوال. نُقل إلى وحدة مستقلة.
7. **عدّادات الأحرف تُقرأ معكوسة** — أرقام محايدة الاتجاه في سياق RTL. أُضيف `dir="ltr"`.

## ١١. حدود معروفة

هذه قيود واعية وموثّقة، لا أخطاء:

1. **تحديد المعدّل في ذاكرة العملية.** كافٍ لخادم واحد أو عدد محدود من النسخ. عند
   التوسّع أفقيًا يجب استبداله بمخزن مشترك (Redis / Upstash). المكان: `lib/rate-limit.ts`.
2. **لا رفع صور من اللوحة.** الحقول تقبل مسارًا داخليًا أو رابطًا خارجيًا. الربط مع
   مزوّد تخزين (S3 / Cloudinary / UploadThing) خطوة مستقلة.
3. **لا محرّر مرئي.** المحتوى يُكتب بـ Markdown. هذا خيار مقصود (مصدر نظيف، تعقيم أسهل،
   لا HTML مشوّه)، لكنه يفترض إلمام المحرّرة بالصيغة.
4. **البحث بـ `contains`.** مناسب لعشرات ومئات المقالات. عند تجاوز بضعة آلاف يُنصح
   بالانتقال إلى الفهرسة النصية الكاملة في PostgreSQL (`tsvector` + `GIN`).
5. **عدّاد القراءات إرشادي.** يمكن تضخيمه نظريًا رغم فحص الأصل وتحديد المعدّل.
   القياس الموثوق مهمة GA4، وهذا موضّح للمحرّرة في اللوحة.
6. **حقل التاريخ يستخدم توقيت الخادم.** `datetime-local` يُنسَّق ويُفسَّر بتوقيت الخادم؛
   إن اختلف عن توقيت المحرّرة فقد يزيح موعد الجدولة. حلّه إضافة اختيار منطقة زمنية صريح.
7. **مزامنة النشرة أحادية الاتجاه.** إلغاء الاشتراك من داخل رسالة المزوّد لا ينعكس
   في قاعدتنا؛ يلزم ربط webhook.
8. **لا اختبارات وحدة (unit) في المستودع.** توجد مجموعة اختبارات متصفّح شاملة في
   `tests/e2e.mjs` (٢٩ فحصًا)، لكنها تتطلّب خادمًا يعمل وقاعدة بيانات معبّأة. إضافة
   Vitest لاختبار الوحدات (التعقيم، فحص السيو، التحقّق من المدخلات) وربط الاثنين
   بـ CI خطوة موصى بها قبل توسّع الفريق.
9. **الصور النائبة SVG.** خفيفة ومناسبة للتسليم، لكنها ليست صورًا تحريرية حقيقية.
   يُنصح باستبدالها بصور مرخّصة قبل التقديم لأي برنامج إعلانات.
10. **لا حذف ناعم.** حذف المقال نهائي. سلة محذوفات إضافة مباشرة على المخطّط الحالي.

## ١٢. تحسينات مقترحة لاحقًا

**قريبة المدى**
- رفع الصور من اللوحة مع قصّ تلقائي وتوليد أبعاد.
- سلة محذوفات (`deletedAt`) وسجلّ تغييرات للمقالات.
- معاينة مباشرة لـ Markdown داخل المحرّر.
- webhook لإلغاء الاشتراك من مزوّد البريد.
- إضافة Vitest للوحدات و Playwright كمجموعة اختبارات دائمة في CI.

**متوسطة المدى**
- بحث نصّي كامل بـ PostgreSQL مع ترجيح العنوان.
- صفحة كاتبة موسّعة (تخصّصات، إحصاءات).
- ترجمة الواجهة (البنية جاهزة: كل النصوص في المكوّنات وقابلة للاستخراج).
- تقارير أداء المحتوى داخل اللوحة عبر Google Analytics Data API.

**التوسّع المستقبلي (المخطّط يستوعبه)**
مراجعات المنتجات، المقارنات، التسويق بالعمولة، متجر، منتجات رقمية، مقالات مموّلة،
فيديو وبودكاست، حسابات مستخدمين، تقييمات ومفضّلة. النماذج الحالية (`Article`،
`Category`، `Tag`، `Author`) مصمّمة لتقبل جداول مرتبطة دون هجرات مدمّرة.

## ١٣. قائمة ما قبل النشر

الخطوات التفصيلية لـ Supabase وVercel في [`README.md`](./README.md#النشر-على-vercel--supabase).

**قاعدة البيانات**
- [ ] إنشاء مشروع Supabase وحفظ كلمة مرور القاعدة.
- [ ] `DATABASE_URL` = رابط Transaction pooler ‏+ `?pgbouncer=true&connection_limit=1`.
- [ ] `DIRECT_URL` = رابط Session pooler (لا الاتصال المباشر — قد يكون IPv6 فقط).

**Vercel**
- [ ] Root Directory = `jamalik` إن بقي المشروع في مجلد فرعي.
- [ ] Production Branch = `main`.
- [ ] ترك Build Command فارغًا — يُستخدم `vercel-build` تلقائيًا.
- [ ] توليد `AUTH_SECRET` بـ `openssl rand -base64 48`.
- [ ] `NEXT_PUBLIC_SITE_URL` بلا شرطة في النهاية (يُخبز في canonical و sitemap و OG).
- [ ] `SEED_ADMIN_EMAIL` و `SEED_ADMIN_PASSWORD` بقيم حقيقية.
- [ ] `RUN_SEED=true` لأول نشر فقط.

**بعد أول نشر**
- [ ] **حذف `RUN_SEED`** — وإلا أُلغيت التعديلات التحريرية عند كل إعادة بناء.
- [ ] تغيير كلمة مرور المدير من `/admin/account`.
- [ ] إدخال معرّف GA4 وقيمة تحقّق Search Console من الإعدادات.
- [ ] رفع `sitemap.xml` إلى Search Console.
- [ ] تحديث `NEXT_PUBLIC_SITE_URL` وإعادة النشر عند إضافة نطاق مخصّص.

**المحتوى والسياسات**
- [ ] استبدال الصور النائبة بصور تحريرية مرخّصة.
- [ ] مراجعة الصفحات القانونية وتحديث بيانات الجهة المالكة وبريد التواصل.
- [ ] إبقاء AdSense معطّلًا حتى يُقبل الموقع فعليًا في البرنامج.

**اختياري (تجميلي، لا يؤثّر على النشر)**
- [ ] إعادة تسمية المستودع.
- [ ] جعل `main` الفرع الافتراضي في GitHub — Vercel ينشر من `main` عبر إعداده الخاص بغضّ النظر.
